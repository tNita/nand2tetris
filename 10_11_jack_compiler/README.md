# Jackコンパイラ

```sh
python3 jack_analyzer.py sample/Square
python3 jack_analyzer.py sample/Square/Main.jack
bash run_regression_tests.sh
```

コンパイル時に以下の型検査を行います。エラー時はファイル名・行・列とサブルーチン名、期待する型・実際の型を表示し、終了コード1で終了します。そのファイルの既存VM出力は上書きしません。

- 変数への代入、二項演算・単項演算、`if` / `while` の条件
- `Array` への添字アクセスと添字の数値型
- `return` の値と宣言された戻り値型、コンストラクタの戻り値型
- サブルーチンの引数の型・個数、メソッドと関数・コンストラクタの呼び出し方
- 式中での `void` 呼び出し、`function` 内での `this`・フィールド参照

宣言を先に収集するため、後で定義したサブルーチンや相互参照も検査できます。ディレクトリ指定時は対象の全Jackファイル、単一ファイル指定時は同じディレクトリのJackファイルから宣言を読み取ります。標準OSの8クラスの宣言も組み込まれており、OSソースを渡すとその宣言を優先します。

`int` と `char` は互換、条件式は `boolean`、`null` は参照型に代入できます。`&`・`|`・`~` は数値のビット演算と真偽値の論理演算に対応します。Jackの `Array` は型のないメモリ領域として扱い、要素は任意の値を保持できます。`Array` と数値・オブジェクト参照の変換も許可します。

宣言のない外部クラスは別途コンパイルされるものとして呼び出しを許可し、その引数・戻り値の型検査は省略します。全分岐での `return` の存在や、未初期化変数の使用などの制御フロー解析は行いません。

回帰テストは型検査の正常系・異常系に加え、既存サンプルのVM出力との一致を確認します。

## 型検査の実装方針

宣言の収集と本体のコンパイルを分け、本体の再帰下降解析中に式の型を求めます。型検査用の抽象構文木は作らず、既存のVMコード生成処理に型情報の伝播と検査を組み込む構成です。

### 1. サブルーチンの宣言を先に収集する

`TypeRegistry.from_files()` は対象ファイルをトークン化し、クラスごとにサブルーチン名と `SubroutineSignature` を登録します。シグネチャには種別（`constructor` / `function` / `method`）、戻り値型、明示的な引数の型の並びを保持します。この段階では本体を波括弧の対応で読み飛ばします。

全対象ファイルの宣言を集めてから本体をコンパイルすることで、定義順に依存せず、前方参照・再帰呼び出し・クラス間の呼び出しを検査できます。標準OSのシグネチャを初期値として登録し、ソースがあるクラスはその宣言で置き換えます。

### 2. 項から式へ型を伝播させる

型は `int`、`boolean`、クラス名などの文字列で表します。`compileTerm()` はVMコードを生成すると同時に、リテラル・変数・呼び出しなどの型を返します。変数の型は既存のシンボルテーブルから取得し、サブルーチン内の宣言をクラス内の宣言より優先します。

`compileExpression()` は左の項の型と次の項の型を `binary_type()` に渡し、演算が成立するかを検査して結果型を得ます。単項演算には `unary_type()` を使います。例えば `1 + 2` の結果型は `int`、`1 < 2` は `boolean` となり、`1 + true` は演算の検査で拒否されます。括弧内の式や呼び出しの戻り値も、同じ仕組みで外側の式へ伝播します。

### 3. 値を使う位置で期待する型と照合する

型の互換性は `is_assignable()` に集約し、`require_type()` で期待する型と実際の型を照合します。代入先には変数の宣言型、条件式には `boolean`、配列の添字には数値型、`return` には現在のサブルーチンの戻り値型を要求します。配列アクセスの対象が `Array` であることも確認します。

呼び出しは `_compileCall()` に集約します。引数の式をコンパイルして型のリストを作り、シグネチャの引数の個数・型と比較します。さらに、インスタンス経由のメソッド呼び出しとクラス経由の関数・コンストラクタ呼び出しを区別します。メソッドの暗黙の `this` はVMの引数数にだけ加え、宣言された引数との比較には含めません。

`void` の呼び出しは `do` 文で許可し、値として使う式では拒否します。現在のサブルーチンの種別と戻り値型も保持し、`function` 内のインスタンス参照や、値の有無を含む `return` の整合性を検査します。

### 4. 型が確定しない値を明示的に扱う

配列要素には内部型 `WORD`、宣言のない外部クラスの呼び出し結果には `UNKNOWN` を使います。どちらも `void` 以外の型との照合を許可しますが、用途を分けることで、型のないメモリと宣言情報の不足を区別しています。配列要素同士の `&`・`|` や配列要素への `~` も、数値・真偽値のどちらとして使うかを早期に固定しないように扱います。

宣言が見つかっているクラスでは、存在しないサブルーチンの呼び出しをエラーにします。外部クラスを許可する方針は、クラス名の誤記や宣言の不足を完全には検出できないという制約を伴います。

### 5. エラーを報告し、出力を確定する

型の不整合は `TypeCheckError` として通知します。`CompilationEngine.compileClass()` は本体の検査エラーにトークナイザの現在位置とサブルーチン名を付け、CLIは標準エラー出力に表示します。

`compile_file()` はVMコードを一時ファイルに書き、コンパイルとファイルのクローズが成功した後に `os.replace()` で出力を確定します。失敗時は一時ファイルを削除するため、そのファイルの既存VM出力を保持できます。出力の確定はファイル単位で行います。

### ファイルごとの役割

| ファイル | 役割 |
| --- | --- |
| `type_checker.py` | 型の互換性、演算の結果型、OSの宣言、シグネチャの事前収集 |
| `compilation_engine.py` | 解析中の型の伝播、各文・呼び出しの検査、エラーへの文脈付与 |
| `symbol.py` | 変数の宣言型とスコープの管理 |
| `jack_tokenizer.py` | エラー報告に使うファイル名とトークン位置の保持 |
| `jack_analyzer.py` | 宣言収集とコンパイルの実行順序、CLIでの報告、VM出力の確定 |
| `test_type_checker.py` | 型不一致の拒否、型の互換性、呼び出し、失敗時の出力保護の検証 |
